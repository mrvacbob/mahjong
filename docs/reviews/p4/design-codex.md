# Phase 4 design review — codex

## Findings

1. **Blocker (§§4, 6) — Define the league ladder, estimand and confirmation gate.** Level 1 contains two different controls and has no unique predecessor relationship. A weak defensive policy can also finish ahead of random without becoming a useful offensive baseline. Keep random, tsumogiri and folder as controls, with shanten as the first candidate against a predeclared control (tsumogiri is the closest discard-policy comparison). Confirm shanten → menzen → yaku → caller → digital as the main chain. Keep occult and strong bots out of the adjacent gate. In a one-versus-three lobby record candidate improvement as mean baseline placement minus candidate placement. With distinct ranks summing to 10, this is exactly 4/3 times (2.5 minus candidate placement). The three baseline seats provide no independent replicates. Use engine ranks including the initial-seat tie-break and engine adjusted scores including oka separately. Freeze policies, comparison direction, effect size for power, and block budget using pilot seeds. Confirm on fresh seeds. If every predeclared edge under both rules must pass, the conjunction is an intersection-union gate and needs no multiplicity correction for that single global claim. Use simultaneous intervals for separately advertised edges if claiming joint coverage. Give failed edges an inconclusive outcome when intervals remain wide. A revision needs fresh confirmation or a predeclared sequential procedure.

2. **Blocker (§§1, 4, 5) — Specify blocks and preserve the external wall boundary.** Internally, one block is one private wall seed across the complete set of distinct permutations (4 for 1v3, 6 for 2v2, 12 for 2+1+1, 24 for four distinct), with a contrast averaged across permutations. For 2v2 use the difference between the two per-game team means. For reciprocal 1v3 include both directions as separate effects, and if the designs share a seed treat all eight games as one block. Cross-lobby comparisons or fits must resample the whole bundle wherever a seed is shared. For external games use fresh system entropy per game. A balanced round of seat assignments then has independent walls, and can be treated as one independently generated balanced block, including both directions if scheduled together. Duplicate walls for external bots would let a stateful bot learn from an earlier game, and the current driver and README already require keeping seeds and logs from players. Rotation balances initial seat and tie priority. Calls, repeats and early ends change who gets subsequent draws or whether a hand occurs, and the engine indexes walls by hands dealt. Blocking accounts for correlation without assuming luck cancels. Precompute the schedule independently of worker order, use independent private wall and bot seed domains, tag bot streams by game and seat, finish all assigned games, and keep replay manifests private until evaluation ends. The current subprocess inherits the referee environment and working directory. A process group provides cleanup. For untrusted competitors use an isolated working directory and execution environment with no access to referee artifacts, shared state across games or other seats' streams. 3. **Should-fix (§4) — Put uncertainty and a realistic game budget in the arena contract.** For mean rank differences use a Student-t interval on independent block means (and a block bootstrap as a sensitivity check). Rank is bounded and ordinal, but the mean of its explicitly assigned numeric values is the target and the block mean supports this inference at the proposed sample sizes. Use a block bootstrap for rank shares and ratios such as wins per hand, resampling full blocks and recomputing numerator and denominator. Define exposures and how double ron counts. For 80% power under a two-sided 95% interval, the planning approximation is B = ((1.96 + 0.84) × SD(block) / effect)^2. In candidate placement units a uniform rank has SD 1.118. Four independent games imply block SD 0.559, so detecting 0.05, 0.03 or 0.02 needs about 980, 2,723 or 6,125 blocks respectively (3,920, 10,892 or 24,500 games per edge per ruleset). If paired block SD is 0.80 the same targets need about 2,008, 5,576 or 12,544 blocks (8,032, 22,304 or 50,176 games). These are planning assumptions. Estimate SD and throughput by format in a pilot before promising a minutes-long run. Report blocks, games, CI, time and the achieved precision. [bots.md](../../design/bots.md)

4. **Should-fix (§4) — Specify a rating fit and check its assumptions.** Predeclare a connected matchup schedule within each ruleset and length, with common anchors if some bots are costly. Fit the Plackett–Luce likelihood over four labeled seats with the same strength parameter for repeated copies, retaining each copy in the risk set until ranked. Anchor the strength scale and include an initial-seat effect or validate its omission with balanced results. Use block bootstrap refits for intervals and report treatment of separation if a fit diverges. Check predictions against reciprocal 1v3 and 2v2 or mixed-lobby results. Call behaviour changes with opponent composition, so a single rating can mask real matchup effects. Publish direct effects alongside ratings. Keep a Tenhou table that connects the strong bots to the ladder and a Mahjong Soul ladder table. [bots.md](../../design/bots.md) · [Game.swift](../../../Sources/Riichi/Game.swift)

5. **Should-fix (§3) — Give controls and menzen executable definitions.** Make level 0 uniformly sample legal actions with an unbiased bounded draw (the existing BotRNG uses modulo). For all other controls and levels 2–5 take a legal win first and define the rest of the action priority. Tsumogiri takes a drawn discard when available, otherwise the first legal discard, passes reactions and skips declarations. Folder does the same except for a lexicographic discard key: against declared threats minimize the count lacking genbutsu, then the count lacking either genbutsu or suji, then maximize visible copies and use stable legal order. With no declared threat, use visible copies then stable legal order. At level 2 specify minimum shanten, maximum unseen ukeire, stable order, no calls/kans/abort, and immediate riichi when offered. At level 3 pick minimum shanten, then maximum ukeire. Break remaining ties by number of distinct live one-draw successors whose best legal discard preserves minimum resulting shanten and admits a closed all-simples route or a pinfu route to tenpai at that shanten. Define that route by a standard completion with all simples, or four sequences, non-value pair and a two-sided wait, respectively. Then compare retained visible-indicator dora plus red count and use stable order. In tenpai replace that successor test with unseen winning copies, then unseen copies on two-sided waits, then dora (score the completed shapes for pinfu). Against a pending or accepted riichi, fold if the best legal discard leaves shanten ≥2, and evaluate that trigger before a riichi declaration. Use own-pond and passed-riichi genbutsu for future discards. The helper also exposes temporary safety, which can expire before the next discard and must be tracked through observed draws or omitted in projections. Hold menzen's attack and defence changes as two ablations under the same name to see which accounts for any gain. 6. **Should-fix (§3) — Define yaku-aware offense and call counterfactuals.** Keep level 3's fold trigger and use its attack policy beyond two shanten. From two shanten down, score each legal discard by bounded public-information lookahead: expand unseen draws without replacement by copy count, allow stable best discards and stop at legal completion, exhaustion of a fixed horizon (e.g. three own draws) or the live-wall limit. Pin the horizon, branch pruning and budget before comparing bots. Enumerate standard, seven-pairs and kokushi completions and use engine scoring on endpoints. Preserve red identity, require yaku independent of dora, and distinguish tsumo and ron, including own-discard furiten on the post-discard wait set and temporary furiten expiry. Use the same explicit turn- and wait-class ron hazard for every candidate if including ron in the offensive model. Zero unseen copies means zero immediate completion weight. Score paid points including known dora and honba, with unknown ura and ippatsu omitted for the first model. Compare best riichi candidate with best damaten and account for stick outlay, lost discard flexibility and ron on riichi-only hands. Document any simplification to those continuation terms and choose damaten on ties. The pre-declaration action list offers a riichi action, not its legal discards. Expose a pure helper using the engine's eligibility rule and remember the intended discard for the second prompt. Level 5 should compare pass against each legal chi/pon plus its best mandatory kuikae-legal discard, asking for both a shanten gain and higher offense value with a live scored yaku route. Include chinitsu among ordinary possibilities through the same scoring path. Start with no optional kans or specify their replacement-draw, robbing and dora model before including them. “Kans when safe” has no reproducible meaning. Test one live copy, karaten, value-pair pinfu failure, open dora without yaku, and riichi-only ron. 7. **Should-fix (§3) — Make digital a bounded expected-utility policy.** Use the same candidate generators for every action and compare pass with each call and riichi with damaten. For each discard estimate seat-specific ron hazard from tenpai likelihood (riichi, open meld count and turn) times a conditional tile risk table (persistent genbutsu zero, then disjoint suji, wall and live classes split for honors). Model open hands explicitly, using exposed yaku, dealer and visible bonus tiles for losses. Combine hazards into a single outcome distribution, including joint rons and the ruleset's resolution, then allocate remaining mass across own win, other win, and draws with tenpai payments. Charge continuation risk across the same finite horizon when comparing folding and pushing. Track score deltas for all four seats (including stick/honba transfers). Early, use score change as a utility approximation. At possible last hands use engine settlement, including extension, bust, dealer repeat and tie-break, to score terminal outcomes by negative placement. For continuing outcomes use a frozen continuation approximation, for example rank expectations over score shocks by remaining scheduled hands and dealer, calibrated on self-play. Specify deterministic fallback when probabilities are sparse, caps and tie order. Use identical public views to check that a third open meld can increase pressure, that a lead can favor a fold, and that a cheaper win that locks up first can outrank a higher-value push. Use head-to-head and ablations to verify the risk and placement terms. 8. **Blocker (§§2, 5–6) — Make prompt binding an explicit external adapter requirement.** The current Swift driver passes a seat-only prompt to Player.receive, then makes the native decision after any trailing indicator. That is enough for a native Bot wrapper, but the wire sends only the masked event and requires one object reply immediately. Mortal's default CLI emits no line when react returns None. Its review mode emits fallback none but changes evaluation and appends a GRP result. Wrap react directly, pass can_act from this seat's prompt, emit one flushed object per event and bind the played action to that prompt. Decide and document that external inference sees the prompt prefix before any trailing indicator, then measure that policy under Tenhou and exercise the chained-indicator case before claiming parity under Mahjong Soul. Never advertise that another seat had a decision. Akochan's TCP client requires hello/join, expects possible_actions to trigger another player's discard reaction and hard-codes East-only metadata. Its stdio pipe takes a tactics file and seat ID, can skip output altogether, emits arrays, and triggers only on an own draw or opponent discard/added kan. A dedicated stdio shim should keep the masked record, add start_game kyoku_first (0 for South, 4 for East) and aka_flag, invoke the AI only for the seat's offered prompts, emit one object, and queue a compound call/riichi answer's discard until the matching own chi, pon or reach event. Validate both halves and handle closed-kan rob prompts explicitly even if unsupported by the policy. Supply the seat from start_game or a per-seat launcher. Preserve red tiles, score updates, unknown tiles and ura-marker aliases. Add golden wire conversations for notifications, round ends, dora ordering, riichi/call continuations, kan robbing, multi-ron and nine terminals. An unsupported action must have an explicit capability report and any fallback counted. Package I can start build work independently, but its measurement depends on these shims. ## Open questions

1. **Ruleset.** Confirm the native ladder in both presets with separate ratings. Use Tenhou hanchan for the first external comparison and bridge all strong bots to native anchors there. Evaluate Mahjong Soul external play separately after dialect and rules coverage.
2. **Length.** Use hanchan for the official gate. East-only is a development and throughput screen. It changes the placement incentives and has its own effects and ratings.
3. **Digital scope.** Use a bounded public-information hazard and value model with explicit open-hand and placement terms. Freeze a small, documented table from permitted data or self-play. Stop before a full opponent hand model. Tile-class hazard alone leaves the action objective undefined.
4. **Occult.** Implement as a parameterized caller variant if the control is desired. It needs a frozen hypothesis and its own matchup against caller, with no package or ladder gate of its own.
5. **Fitting from logs.** Owner decision. The roadmap records restrictions and the intended transition to self-play. Obtain a source-specific decision for fitting and for publishing derived tables before relying on those records. Use self-play or explicitly permitted data as the default and retain provenance and holdouts. Small aggregate output and private inputs do not establish permission.

## Verdict

Revise before implementation handoff. Freeze the gated ladder and the arena block/replay contract, and specify the Mortal and akochan prompt adapters before collecting benchmark results. Native policies can use the existing seat-view boundary with pure analysis helpers.
